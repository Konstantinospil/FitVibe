## Keyboard alternatives in the Planner (2026-11-26)

Every drag in the Calendar has two keyboard paths. Moves start on a session's move handle: the grip button on a session card, or the session chip in the week and day views. Length changes start on the resize handle under a chip in the week and day views.

| Key                         | While nothing is picked up                                  | While a session is picked up                                                   |
| --------------------------- | ----------------------------------------------------------- | ------------------------------------------------------------------------------ |
| <kbd>Space</kbd>            | Picks the session up                                        | Drops it on the highlighted day or hour                                        |
| <kbd>Enter</kbd>            | Opens the **Reschedule workout** dialog (day, time, length) | Drops it on the highlighted day or hour                                        |
| <kbd>←</kbd> / <kbd>→</kbd> | —                                                           | Previous / next day                                                            |
| <kbd>↑</kbd> / <kbd>↓</kbd> | —                                                           | Month view: previous / next week. Week and day views: one hour earlier / later |
| <kbd>Esc</kbd>              | —                                                           | Cancels the move                                                               |

- Moves stay inside the days on screen. In the day view, left and right do nothing; use the dialog to change the day.
- On a resize handle, Space picks up the session's end; <kbd>↓</kbd> / <kbd>↑</kbd> make it 15 minutes longer / shorter (5–720 minutes), Enter or Space saves and Esc cancels. Enter on its own opens the same dialog.
- Picking up, each step (including any conflict at the highlighted target), dropping and cancelling are announced in a polite live region; focus stays on the handle and returns to it after the move.
- Conflicts are refused before saving, exactly as for pointer drags.
- Evidence: `tests/frontend/hooks/useKeyboardMove.test.tsx`, the keyboard tests in `tests/frontend/pages/Calendar.test.tsx`, and the keyboard scenarios in `tests/frontend/e2e/calendar-scheduling.spec.cjs` (month and week views).
